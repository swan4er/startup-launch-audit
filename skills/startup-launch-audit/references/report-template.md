# Шаблон отчёта

Отчёт — `report.md` в папке проекта; из него собирается `report.html`. Пиши его последним, когда карточка заполнена, а `calc.json` и `tables.md` посчитаны.

## Правила текста

- **Для кого пишешь.** Для основателя, простыми словами. Термин при первом упоминании — с расшифровкой в скобках; в приложении — глоссарий.
- **Сначала вывод, потом обоснование.** Без вежливых подводок: «Идея слабая: никто не платит за решение этой проблемы», а не «Интересная идея, но…».
- **Метка у каждой цифры:** `[факт](ссылка)`, `[оценка]`, `[допущение]`. Цифры расчётов — только из `tables.md` и `calc.json`, без пересчёта в уме.
- **Ничего не выдумывай.** Ни отзывов, ни кейсов, ни метрик, ни сообществ. Вместо них — заглушки `[вставить отзыв]`, `[вставить цифру после теста]`.
- **Не описывай, как устроен разбор.** Никаких «посчитано скриптом» или «по файлу с порогами» — только суть и вывод.
- **Одна главная рамка на вопрос.** Не нагромождай методики: одна таблица или один список, который отвечает на вопрос раздела.
- **Стадия «идея»:** разделы «Метрики» и «Масштабирование и PMF» — план (что измерять, какие пороги нужны), а не анализ несуществующих данных.
- **Язык отчёта — язык пользователя.** Заголовки ниже переводи, если пользователь пишет не по-русски.
- **Длина.** «Коротко» — один экран. Остальные разделы — сколько нужно для решения, без пересказа очевидного.

## Структура `report.md`

Нумерация, заголовки и маркеры графиков — ровно такие, как ниже. Маркер `<!-- chart:… -->` стоит на отдельной строке: в Markdown он не виден, в HTML превращается в график.

Для стадии «есть платящие»:
- **Вердикт в «Коротко»:** «Масштабировать / Докручивать / Менять сегмент или продукт», а не «Делать / Проверить / Отложить». Итог шкалы оценки идеи всё равно показывается в разделе 5, но решение принимается по чек-листу готовности и тесту PMF из `metrics-scaling.md`.
- **Раздел 14 называется «План на 2–4 недели».**

## Что в каком разделе

| Раздел | Откуда | Что обязательно |
|---|---|---|
| 1. Коротко | всё ниже | Вердикт, итог, надёжность, 3 риска, одно действие на сегодня, не больше 2 шагов дальше |
| 2. Проблема и клиент | `validation.md` | Ответы на три вопроса: кто конкретно платит, как решает сейчас, почему перейдёт. Сила боли и её доказательства — по лестнице доказательств. Если ответа нет, так и написать: это главный риск |
| 3. Спрос и конкуренты | `validation.md`, `research.md` | Чек-лист спроса с отметками; таблица конкурентов (цена, что хвалят, что ругают, ссылка); таблица болей из отзывов; стоп-факторы |
| 4. Рынок и прогноз | `market.md` | Сегменты и стартовый сегмент; TAM / SAM / SOM с расчётом, сверка снизу и сверху; рост; выручка и доля SAM по годам |
| 5. Оценка идеи | `validation.md` | Таблица «Оценка идеи» из `tables.md`, сработавшие ограничители словами, что поднимет балл |
| 6. Портрет клиента | `audience-offer.md` | Портрет из 8 полей — один конкретный человек; альтернативы клиента, включая «ничего не делать» |
| 7. Позиционирование и оффер | `audience-offer.md` | 3 позиционирования, 3 оффера, проверка по чек-листу, лучший вариант и как проверить заголовки |
| 8. Экономика и прогноз выручки | `economics.md` | Цена и модель оплаты с обоснованием; таблицы «Юнит-экономика», «Прогноз выручки», «Чувствительность», «Цель» из `tables.md`; что изменить в первую очередь |
| 9. Каналы | `channels.md` | Матрица каналов, 2–3 стартовых канала с циклом проверки, круги доверия для первых клиентов, найденные площадки со ссылками |
| 10. Лендинг | `landing.md` | Проверка существующего по 15 пунктам или структура будущего из 7 блоков; целевые конверсии |
| 11. Метрики | `metrics-scaling.md` | Воронка AARRR для этого продукта, Aha-момент, когорты, дашборд (`dashboard.csv`) |
| 12. Масштабирование и PMF | `metrics-scaling.md` | Чек-лист готовности; тест Шона Эллиса; для запущенных — разбор «почему не идёт» |
| 13. Риски и допущения | `validation.md` | Опасные допущения (критичность × неопределённость) с проверкой, порогом и условием остановки; «почему это провалилось» — заранее; путь разворота; проверка по типовым ошибкам |
| 14. План на 7 дней | `validation.md` | Задачи по дням списком `- [ ]`, у каждой — ожидаемый результат; проверки опасных допущений встроены в план |

| Б. Шаблоны сообщений | `channels.md` | Личное сообщение под эту ЦА, повторное напоминание, пост для сообщества |
| В. Черновик лендинга | `landing.md` | Текст 7 блоков с заглушками вместо отзывов и цифр |

## Глоссарий

| Термин | Простыми словами |
|---|---|
| Aha-момент | Первое действие, после которого клиент понял ценность продукта |
| AARRR | Пять этапов пути клиента: привлечение, активация, удержание, доход, рекомендации |
| ARPU | Средний доход с одного клиента в месяц |
| CAC | Сколько стоит привлечь одного платящего клиента: все затраты на привлечение, делённые на число новых клиентов |
| Churn (отток) | Доля клиентов, ушедших за месяц |
| CR (конверсия) | Доля людей, перешедших на следующий шаг: из посетителей в регистрации, из регистраций в оплаты |
| CTA | Призыв к действию — главная кнопка или просьба на странице |
| ICP | Портрет идеального клиента — один конкретный человек, а не «все» |
| K-фактор | Сколько новых пользователей в среднем приводит один пользователь |
| LTV | Сколько валовой прибыли клиент принесёт за всё время, пока платит |
| LTV/CAC | Во сколько раз клиент приносит больше, чем стоит его привлечь |
| MRR | Выручка от подписок за месяц |
| MVP | Минимальная версия продукта, на которой можно проверить спрос |
| PMF | Продукт нашёл свой рынок: клиенты расстроятся, если он исчезнет |
| SAM | Часть рынка, которую можно обслужить: нужная география, язык, сегмент |
| SOM | Часть рынка, которую реально занять за 1–3 года |
| TAM | Весь теоретический рынок — все, кому в принципе нужен продукт |
| Валовая маржа | Доля цены, которая остаётся после переменных затрат (API, эквайринг, налог) |
| Окупаемость CAC | За сколько месяцев клиент возвращает деньги, потраченные на его привлечение |
| Smoke-тест | Проверка спроса до продукта: лендинг, пост или предпродажа |
| Когорта | Клиенты, пришедшие в один период; их сравнивают между собой |
| Лестница доказательств | От слабого к сильному: мнение → намерение → контакт → предоплата → регулярное использование |
| Build in Public | Открытая разработка: делиться процессом и цифрами публично |

## Выжимка в чат

Когда файлы готовы, напиши в чат коротко:
- вердикт и итог;
- три главных риска;
- действие на сегодня;
- пути к `report.md`, `report.html`, `dashboard.csv`, `card.md`;
- одной строкой: проведёшь интервью или тест — возвращайся с результатами, разбор обновится.
